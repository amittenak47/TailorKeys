# Built-in English next-word model

This is a standalone training/export/runtime pipeline. It does not integrate the
model into Predictor, the Android service or the iOS view controller. There are
no mobile runtime dependencies: Kotlin uses primitive arrays and signed int8
matrix products; Swift uses preallocated arrays and Accelerate's int8 widening
and float dot products. Both hold full recurrent state for the sentence so far.

## Rerun on this Windows machine

All data, caches generated by this pipeline, training logs and checkpoints belong
in `..\tk-lm-data`. Never add them to git. Python 3.10 is
used because the existing 3.14 installation need not have CUDA wheels.

```powershell
$data = '..\tk-lm-data'
$env:UV_CACHE_DIR = "$data\package-cache"
uv venv --python 3.10 "$data\venv"
uv pip install --python "$data\venv\Scripts\python.exe" torch==2.11.0 --index-url https://download.pytorch.org/whl/cu128
uv pip install --python "$data\venv\Scripts\python.exe" numpy==2.2.6 pyarrow==25.0.1
$python = "$data\venv\Scripts\python.exe"
& $python tools/lm/test_pipeline.py
& $python tools/lm/prepare.py --data $data
& $python tools/lm/train.py --data $data --minutes 75 --validate-every 2000
& $python tools/lm/export.py --data $data
& $python tools/lm/eval.py --data $data --quantized
```

`prepare.py --download-only` fetches and verifies snapshots without preprocessing.
Existing files are checked against the manifest, which pins GitHub/Hugging Face
revisions and download hashes. Preparation streams one document/batch at a time,
deduplicates globally in SQLite with a 32 MiB page cache, counts only dictionary
words, then writes gzip JSONL and memory-mapped uint16 training records. Each
record has a uint16 context length followed by IDs; int64 sidecar offsets count
uint16 elements. Vocabulary ties break alphabetically. Corpus hash modulo 50
selects evaluation; the same normalized sentence cannot cross partitions or
sources. A split change or duplicate clears dialogue context. SODA is sampled by
an independent part of the hash to match CV+Tatoeba target tokens, approximately
50/50; evaluation is never downsampled. At most two previous sentences in the
same document are used. Independent CV/Tatoeba rows are never concatenated.

Training uses embedding 96, hidden/cell 672, one CIFG layer, output projection 96
and tied embeddings (~3M parameters). AdamW, gradient clipping, bfloat16 CUDA
arithmetic, warmup/cosine learning rate, halving on validation plateaus, and
held-out perplexity early stopping are configured in `train.py --help`. The CUDA training path uses cuDNN's fused LSTM
with **input-gate weights/biases constructed as the negative forget gate**,
exactly enforcing `i=1-f` through autograd. Three independent gates are stored.
The PyTorch private fused entry point is version-pinned and tested against the
CPU three-gate equations for both outputs and gradients.

Training windows include context plus the current sentence, at most 64 input
tokens; oldest context is dropped first, keeping complete short sentences.
Sentences longer than the window use random target windows.
Context tokens warm the recurrent state but receive no loss. Sampling is with
replacement, so early stopping and the time budget govern training length rather
than full epochs. `--resume` restores the last checkpoint and optimizer; use the
same settings/total time budget. The selected best checkpoint is exported (0.002-nat minimum validation improvement
for patience; a final smaller improvement is also retained).
Early stopping samples 1,024 evenly spaced held-out sentences per source and
weights their mean losses by sampled training-token proportions. `eval.py`
evaluates **all** held-out sentences, with no context truncation and bounded
64-step GPU chunks. `--limit` is only for smoke tests. Accuracy includes OOV
misses and reports prefixes of zero, one and two letters, per source and overall.
A full evaluation writes `baseline-cache.json` outside the repository. Subsequent
comparisons may pass `--baseline-cache PATH`; all shipped asset hashes, held-out
file hashes and target counts must match before the cached baseline is accepted.
The baseline reproduces the current English scoring from the shipped n-grams and
frequency ranks; see RESULTS.md for the precise comparison and caveats.

## Runtime use

```kotlin
val model = assets.open("lm_en.bin").use { NextWordModel.load(it) }
val state = model.initialState()
model.step(state, model.idOf("<s>"))
model.step(state, model.idOf("hello"))
val out = FloatArray(model.vocabularySize) // allocate once
model.logProbs(state, out)
```

The API accepts IDs; tokenize outside it. Lowercase Unicode letters with internal
apostrophes, normalize curly apostrophes, replace numbers with `<num>`, preserve
commas as `<,>`, and feed sentence boundaries as `</s>`, `<s>`. Missing words map
to `<unk>`. `idOf` normalizes case/apostrophes but does not tokenize or identify
numeric strings. `scoreCandidates` fills **unnormalized logits**, avoiding a full
vocabulary scan when only candidate ordering is needed. Full `logProbs` includes
special IDs; the eventual integration must exclude them from displayed words.
State buffers are allocated once, then `step`, `reset`, `logProbs` and
`scoreCandidates` reuse storage. A state belongs to one model and one text stream;
do not mutate the same state concurrently. Models can be shared across states.
Swift has the same API with `load(from:)`, which opens/closes an InputStream,
and `inout` output arrays. It is picked up by the existing `Keyboard` source folder
in `ios/project.yml`; the binary is a Keyboard resource.

## JVM verification and Android build

Before **each** Gradle command, wait for other Gradle Java processes to disappear:

```powershell
$env:JAVA_HOME = 'C:\Program Files\Java\jdk-23'
while (Get-CimInstance Win32_Process -Filter "Name='java.exe'" | Where-Object { $_.CommandLine -like '*gradle*' }) {
    Start-Sleep -Seconds 30
}
.\gradlew.bat --no-daemon testDebugUnitTest --quiet
while (Get-CimInstance Win32_Process -Filter "Name='java.exe'" | Where-Object { $_.CommandLine -like '*gradle*' }) {
    Start-Sleep -Seconds 30
}
.\gradlew.bat --no-daemon assembleDebug --quiet
```

The JVM tests check the actual asset against original PyTorch reference top-10
IDs/probabilities, normalization, subset scoring, reset, malformed files and word
normalization. A warmed timing loop reports median step and step+full-softmax in
`app/build/reports/lm-benchmark.json`. This host JVM measurement does not establish
latency on an Android tablet. Re-running the final evaluation after JVM checks adds the
asset-bound timing to RESULTS.md. Swift must still be compiled/tested on a Mac; no
device installation is part of this pipeline.
